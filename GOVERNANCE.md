# Governance

Realmroot Adapters is maintained by the Realmroot organization with community
participation.

## Roles

### Contributors

Anyone who participates through issues, proposals, documentation, code,
security research, or review.

### Provider maintainers

Contributors with sustained expertise and ownership of one or more provider
modules. Provider maintainers may triage and review changes in their provider
area but cannot weaken project-wide identity or security contracts.

### Core maintainers

Maintainers responsible for releases, the canonical provider contract,
security invariants, repository administration, and cross-provider decisions.

## Decision making

Routine changes use lazy consensus through pull-request review. Changes to the
provider contract, identity levels, security invariants, compatibility policy,
or governance require an issue or design document before implementation and
approval from a core maintainer.

Security decisions prioritize preserving the Agent, Resource, tenant, and
credential boundaries over compatibility or implementation convenience.

## Becoming a maintainer

Maintainer access is earned through sustained, high-quality contributions,
responsible review, reliable security judgment, and respectful community
participation. Existing core maintainers nominate and approve new maintainers.

## Inactive maintainers

Maintainers may step down at any time. Repository access may be removed after a
prolonged period of inactivity or when needed to protect the project. Prior
contributions and credit remain unaffected.
